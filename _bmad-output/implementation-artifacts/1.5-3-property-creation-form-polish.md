# Story 1.5-3: Property Creation Form Polish

Status: ready-for-dev

## Story

As a new gardener opening the app for the first time,
I want the property creation form to feel welcoming and well-designed,
So that I feel confident getting started and not intimidated by the setup process.

## Acceptance Criteria

1. **Given** the app loads with no existing property
   **When** the property creation form is displayed
   **Then** the form is rendered inside a styled card with subtle shadow, rounded corners, and a warm surface background — not floating on a bare white page

2. **Given** the property creation form
   **When** the user views the input fields
   **Then** all inputs have earth-tone styling: warm border colors, soft focus rings (sage green, not bright green), consistent padding, and rounded corners matching the design system radius scale

3. **Given** the property creation form
   **When** the user views the submit button
   **Then** the button uses the primary sage-green color from the design system with proper hover/active/disabled states — not the raw `bg-green-600`

4. **Given** the property creation form with a validation error
   **When** the error is displayed
   **Then** the error uses the design system destructive color (muted brick red) — not bright red — with appropriate styling

5. **Given** the property creation form
   **When** the optional dimensions section is visible
   **Then** the dimensions fieldset is visually de-emphasized (lighter border, muted legend text) to communicate that it is skip-friendly per UX-DR13

6. **Given** the property is successfully created
   **When** the form transitions to the main canvas view
   **Then** there is a clean visual transition (subtle fade or slide) confirming the creation was successful per UX-DR12

## Dev Notes

### UX-DR13: Skip-Friendly, No Intimidation

The form should communicate that getting started is easy. The required field (property name) should be prominent and inviting. The optional dimensions section should feel like a bonus, not a demand. Consider:
- A warm, friendly heading instead of the current "Create Your Property"
- Brief, encouraging copy
- Visual hierarchy that draws the eye to the name input first

### Current Component State

`PropertyCreationForm.svelte` currently uses these hardcoded color classes:
- Inputs: `border-gray-300`, `focus:border-green-500`, `focus:ring-green-500`
- Button: `bg-green-600`, `hover:bg-green-700`
- Error: `text-red-600`
- Legend: `text-gray-600`

All of these should be replaced with semantic design system tokens.

### Transition Implementation

For the form-to-canvas transition, Svelte's built-in transitions work well:

```svelte
{#if getProperties().length === 0}
  <div transition:fade={{ duration: 250 }}>
    <PropertyCreationForm />
  </div>
{:else}
  <div transition:fade={{ duration: 250 }}>
    <!-- canvas view -->
  </div>
{/if}
```

Note: Svelte 5 transitions may have different syntax — verify with current Svelte 5 docs.

### What This Story Does NOT Include

- Changing form logic or validation rules (already working from Story 1.3)
- Adding new form fields
- Multi-step onboarding wizard
- Property editing form
