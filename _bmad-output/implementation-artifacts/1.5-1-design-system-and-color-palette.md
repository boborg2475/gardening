# Story 1.5-1: Design System & Color Palette

Status: ready-for-dev

## Story

As a gardener,
I want the app to have a cohesive visual identity with muted earth tones,
So that the interface feels like a real gardening tool rather than a generic white page.

## Acceptance Criteria

1. **Given** the Tailwind configuration
   **When** a developer inspects the theme
   **Then** a complete earth-tone color palette is defined with semantic tokens (primary, surface, border, muted, accent) using CSS custom properties and Tailwind theme extensions

2. **Given** the design system palette
   **When** colors are used across the app
   **Then** the palette follows UX-DR6: muted earth tones (sage greens, warm browns, soft stone grays, parchment whites) — no bright gamified colors or red/yellow/green traffic-light patterns

3. **Given** the design system
   **When** text is rendered at any hierarchy level
   **Then** a typography scale is defined with consistent font sizes, weights, and line heights for headings (h1-h3), body, labels, and captions

4. **Given** the design system
   **When** spacing and border radius values are used
   **Then** a spacing system and radius scale are defined and consistent across all components

5. **Given** shadcn-svelte is evaluated
   **When** a decision is made on adoption
   **Then** the decision is documented in dev notes with rationale, and if adopted, the base components (Button, Input, Select, Card) are installed and themed to match the earth-tone palette

6. **Given** the design system tokens
   **When** the app loads
   **Then** the base background is a warm off-white/parchment (not pure white) and the base text is a warm dark brown/charcoal (not pure black)

## Dev Notes

### Color Palette Direction (UX-DR6)

The palette should evoke natural materials — soil, stone, foliage, parchment. Approximate starting point:

| Token | Role | Approximate Hue |
|-------|------|-----------------|
| `--color-primary` | Primary actions, active states | Muted sage green (#6B7C5E or similar) |
| `--color-primary-hover` | Primary hover | Darker sage (#5A6B4E) |
| `--color-accent` | Secondary accent | Warm terracotta/brown (#8B7355) |
| `--color-surface` | Card/panel backgrounds | Warm cream (#FAF7F2) |
| `--color-background` | Page background | Light parchment (#F5F1EB) |
| `--color-foreground` | Primary text | Warm charcoal (#3D3631) |
| `--color-muted` | Secondary text, labels | Stone gray (#8A8278) |
| `--color-border` | Borders, dividers | Warm light gray (#D9D3CB) |
| `--color-input` | Input backgrounds | White with warm tint (#FDFCFA) |
| `--color-destructive` | Error states | Muted brick red (#A85C4A) — not bright red |
| `--color-success` | Completion confirmations (UX-DR12) | Soft olive (#7A8B5C) — not bright green |

These are starting points; final values should be tuned for contrast and harmony.

### Tailwind v4 Theme Extension

Tailwind CSS v4 uses `@theme` in CSS (not `tailwind.config.js`). The approach:

```css
@import 'tailwindcss';

@theme {
  --color-primary: #6B7C5E;
  --color-primary-hover: #5A6B4E;
  --color-surface: #FAF7F2;
  --color-background: #F5F1EB;
  --color-foreground: #3D3631;
  --color-muted: #8A8278;
  --color-border: #D9D3CB;
  /* ... etc */
}

@layer base {
  body {
    background-color: var(--color-background);
    color: var(--color-foreground);
  }
}
```

This makes utilities like `bg-primary`, `text-muted`, `border-border` available throughout the app.

### shadcn-svelte Evaluation Criteria

Evaluate on these axes:
1. **Svelte 5 compatibility** — must work with runes and Svelte 5 component model
2. **Tailwind v4 compatibility** — must work with the `@theme` approach
3. **Bundle size** — should not add significant weight for the few components needed
4. **Theming flexibility** — must accept custom CSS variable-based theming

If shadcn-svelte is adopted, its default CSS variables should be remapped to our earth-tone palette. If not adopted, the same components (Button, Input, Select, Card) should be created as simple Tailwind-styled Svelte components.

### UX-DR12: Completion Micro-Moments

The design system should include a `--color-success` token for task completion confirmations. This is not a traffic-light green but a soft, satisfying olive/sage tone. Animation tokens (transition duration, easing) should also be defined for subtle confirmation animations (e.g., checkmark fade-in, gentle background flash).

### Architecture Compliance

- All theme tokens live in `src/app.css` — single source of truth
- No custom CSS files per component — use Tailwind utilities referencing semantic tokens
- Components reference semantic tokens (`bg-surface`) not raw colors (`bg-[#FAF7F2]`)

### What This Story Does NOT Include

- Restyling individual components (Stories 1.5-2 through 1.5-5)
- Icon selection or icon library setup (handled in Story 1.5-4)
- Canvas-specific visual styling (Story 1.5-5)
- Dark mode support (not in MVP scope)
