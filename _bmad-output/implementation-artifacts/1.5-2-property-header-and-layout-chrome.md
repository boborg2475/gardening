# Story 1.5-2: Property Header & Layout Chrome

Status: ready-for-dev

## Story

As a gardener,
I want the app shell to have a polished, professional layout with proper visual hierarchy,
So that the interface feels like a real tool and I can easily find controls and information.

## Acceptance Criteria

1. **Given** a property exists and the app loads
   **When** the main layout renders
   **Then** the header bar has a styled background (using design system surface/primary colors), proper padding, and the property name is displayed with appropriate typography weight and size

2. **Given** the main layout
   **When** the canvas area is visible
   **Then** the canvas toolbar area (top-right controls) has a semi-transparent panel background with rounded corners and subtle shadow, visually grouping the controls together

3. **Given** the main layout
   **When** the bottom controls area is visible
   **Then** the north orientation controls are styled in a consistent panel matching the toolbar, positioned cleanly at the bottom of the canvas

4. **Given** the property has dimensions
   **When** the header renders
   **Then** the dimensions are displayed in a muted secondary style beneath the property name, with proper spacing

5. **Given** any screen size (mobile or desktop)
   **When** the layout renders
   **Then** the header, canvas, and control panels are responsive and usable — no overlapping elements, no clipped text

## Dev Notes

### Dependency on Story 1.5-1

This story requires the design system tokens from Story 1.5-1 to be in place. All color references (`bg-surface`, `text-foreground`, `border-border`, etc.) come from the Tailwind theme defined in that story.

### Current State of Components

The existing components use hardcoded gray/green Tailwind classes:
- `PropertyHeader.svelte`: `border-b border-gray-200`, `text-gray-600`
- `+page.svelte`: `bg-green-600`, `bg-blue-600`, plain white backgrounds

All of these need to be replaced with semantic design system tokens.

### ControlPanel Component

The floating control panels should feel like translucent overlays on the canvas — present but not dominating. The `backdrop-blur` effect gives a modern glass-panel feel while keeping the earth-tone warmth. If `backdrop-blur` causes performance issues on the canvas, fall back to a solid `bg-surface` with high opacity.

### Layout Structure

Current layout:
```
<div class="flex h-screen flex-col">
  <PropertyHeader />
  <div class="relative min-h-0 flex-1">  <!-- canvas container -->
    <div class="absolute top-2 right-2 z-10">  <!-- top controls -->
    <div class="absolute bottom-4 left-2 z-10">  <!-- bottom controls -->
    <PropertyMap />
  </div>
</div>
```

This structure is sound — the changes are primarily visual (backgrounds, borders, shadows, typography), not structural.

### What This Story Does NOT Include

- Restyling the property creation form (Story 1.5-3)
- Restyling individual control elements like buttons/selects (Stories 1.5-3 and 1.5-4)
- Canvas visual changes (Story 1.5-5)
- Adding icons to the header
