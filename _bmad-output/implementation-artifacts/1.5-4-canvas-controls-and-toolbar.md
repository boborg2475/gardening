# Story 1.5-4: Canvas Controls & Toolbar

Status: ready-for-dev

## Story

As a gardener using the canvas tools,
I want the canvas controls to be well-styled with clear visual affordances,
So that I can easily identify and use each tool without confusion.

## Acceptance Criteria

1. **Given** the canvas view is active
   **When** the Draw Boundary button is visible
   **Then** it is styled with the design system primary color, has an appropriate icon (e.g., a polygon/pen icon), and clearly communicates its purpose

2. **Given** the canvas view is active
   **When** the Grid Scale selector is visible
   **Then** it uses design system input styling (earth-tone borders, rounded corners, proper focus states) and includes a small grid/ruler icon or label for context

3. **Given** the canvas view is active
   **When** the North Orientation controls are visible
   **Then** the input and button are styled consistently with the design system, the label is clear, and the Set North button uses a secondary/accent style (not the same primary as Draw Boundary)

4. **Given** any canvas control button
   **When** the user hovers, focuses, or clicks it
   **Then** proper visual feedback is provided (hover color change, focus ring, active/pressed state) using design system interactive tokens

5. **Given** the Draw Boundary mode is active (drawing in progress)
   **When** the user looks at the toolbar
   **Then** the Draw Boundary button shows an active/engaged state (e.g., different background, border highlight, or "Drawing..." label) to indicate the current mode

6. **Given** the canvas controls
   **When** viewed on a mobile device
   **Then** buttons and inputs have adequate touch targets (minimum 44x44px tap area) and the toolbar does not obscure critical canvas content

## Dev Notes

### Icon Library Recommendation

Lucide is the recommended icon library for this project:
- Lightweight tree-shakeable SVG icons
- Works well with shadcn-svelte (if adopted)
- Has relevant icons: `Pencil`, `Pentagon`, `Grid3x3`, `Compass`, `Navigation`
- Svelte bindings available via `lucide-svelte`

If the team prefers, simple inline SVG icons (3-4 icons total) are also acceptable to avoid a dependency.

### Button Hierarchy

Establish a clear button hierarchy for the app:
- **Primary** (`bg-primary`): Main actions — Draw Boundary
- **Secondary/Accent** (`bg-accent`): Supporting actions — Set North
- **Ghost/Subtle** (`bg-transparent hover:bg-muted/20`): Tertiary actions, future use

This hierarchy helps users quickly identify the most important action on screen.

### Active Drawing State

The Draw Boundary button needs to communicate when drawing mode is active. The current implementation toggles drawing mode via `propertyMapRef?.startBoundaryDrawing()`. The button should reactively show the active state. Options:
- Expose a reactive `isDrawing` state from `PropertyMap`
- Use a shared drawing state store
- Pass a bound state variable

### Current Component References

Files that need updates:
- `src/routes/+page.svelte` — Draw Boundary button, North Orientation controls
- `src/lib/ui/shared/GridScaleSelector.svelte` — Grid scale dropdown

### What This Story Does NOT Include

- Adding new canvas tools or controls
- Canvas visual changes (grid lines, boundaries — Story 1.5-5)
- Undo/redo buttons (future epic)
- Zoom control buttons (pan/zoom is gesture-based from Story 1.4)
